# Agent 文档规则

本目录是「文档驱动开发」的规格来源。生成代码时以这里的文档为准,并**严格遵守以下边界**。

## 目录结构

```
agent/
├── infra/                     # 项目基建文档(路由 / API 请求 / 主题色 / 全局组件 等)
│   ├── request.md
│   ├── theme.md
│   └── i18n.md
└── service/                   # 业务模块文档,按模块划分
    └── <module>/
        ├── <module>-api.md    # 该模块的接口 / 请求层规格
        └── <module>-page.md   # 该模块的逻辑 + UI 规格
```

- `infra/` —— 基建文档。描述路由、api 请求层、主题色、全局组件等**全局共享能力**。
- `service/<module>/` —— 业务文档。每个业务模块一个文件夹,内部拆成 `-api` 与 `-page` 两份。

## 生成代码的硬性规则

### 1. 只动 `service`

- 基于 agent 文档生成代码时,**默认只允许新增 / 修改 service 对应模块的代码**。
- 不得擅自改动基建(路由注册、请求封装、主题 token、全局组件等)。

### 2. 需要动 `infra` 必须先问

- 一旦发现要完成需求**必须**改动基建(新增全局请求逻辑、改路由结构、加主题色、加/改全局组件等),
  **停下来手动询问用户**,说明为什么需要动、动哪里,得到确认后再改。
- 严禁在未询问的情况下顺手改 infra。

### 3. 业务模块代码拆 `-api` 与 `-page`

对每个 `service/<module>`,生成的代码遵循同样的拆分:

- **`-api`** —— 请求层。接口定义、DTO ↔ 前端模型转换、mock 等,遵循项目 `api-request` / `data-fetching` 规范。
- **`-page`** —— 页面层。写业务**逻辑与 UI**,遵循项目 `coding-style` / `ui-style` / `react-19` 等规范。

## 与项目既有规范的关系

`agent/` 文档定义「做什么」;`.claude/skills`(及其 `.cursor/rules` 副本)定义「怎么写」。
两者冲突时,写法以 skills 为准,边界以本文件为准。
